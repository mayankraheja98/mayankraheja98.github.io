🖱 Clickjacking Tester

Load a site in a frame, see whether it can be embedded, and visualise how an attacker would overlay a decoy on top. Use it only on sites you own or are authorised to test.

Target

Attacker's view

A real attack sets opacity to 0 and aligns a sensitive button (delete account, transfer, like…) under a tempting decoy. Here the decoy ignores clicks so you can interact with the frame.

Enter a URL and click “Load in frame”.

Cross-check with headers (definitive)

Browsers hide whether a frame was blocked, so what you see is the real test. For a definitive answer, paste the page's response headers (curl -sI URL).

What does the result mean?

If the target renders inside the frame, any website can embed it. That is clickjacking-prone, but real impact needs a sensitive one-click action. Also, many session cookies are SameSite=Lax/Strict, so a cross-site frame is often logged out; test your page in the state a victim would be in.

  • Add Content-Security-Policy: frame-ancestors 'none' (or 'self' / specific partners).
  • Add X-Frame-Options: DENY or SAMEORIGIN for old browsers.
  • Use SameSite cookies and re-authentication or confirmation for destructive actions.
  • Don't rely on JavaScript frame-busting alone; sandboxed frames defeat it.

If the frame is blank, shows "refused to connect" or a browser error icon, framing is blocked, which is the desired result. Note: this lab is served over HTTPS, so http:// targets are blocked as mixed content and can't be tested here.
